# Импорт и экспорт расходов

## Компоненты

Диалоги в истории расходов: `client/src/components/ImportDialog.vue` и `ExportDialog.vue`. Преобразование/проверки в `client/src/services/expenseImport.ts`, экспорт — в `expenseExport.ts`; операции используют expense store и IndexedDB. Это клиентская функциональность, backend endpoint для файлов не используется.

## JSON import/export

JSON export использует `format: "finfast"`, `version: 3`, массив `expenses` и массив определений используемых custom categories (`id`, `name`, `icon`, `color`). В расход входят expense ID, amount, currency code, system `categoryId` и/или custom `customCategoryId`, `createdAt`, описание и payment date; userId и sync flags не экспортируются. Импорт поддерживает версии 1, 2 и 3. В версиях v1/v2 отсутствующее поле валюты трактуется как BYN. Для v2/v3 категории проверяются до записи расходов; отсутствующие в текущем профиле категории создаются с новыми профильными ID, после чего ссылки расходов переназначаются. v1 остаётся совместимым, но не содержит custom category metadata.

Валидация выполняется для всех записей до merge; если файл невалиден, сохранение не должно начинаться. Merge идентифицирует дубликаты по expense ID в текущем user-scoped наборе: совпавшая запись обновляется и помечается unsynced, новая добавляется как unsynced. После merge UI сохраняет результат и перезагружает local store. Сам импорт не отправляет немедленно API sync.

Текущая проверка даты принимает всё, что парсит `Date`, а не строго ISO-8601; UUID regex допускает lowercase hex только. Повторяющиеся IDs внутри импортируемого массива отдельно не отвергаются. При изменении формата/version сохранять совместимость явно, не менять version 1 содержимое незаметно.

## CSV export

CSV содержит локализованные заголовки даты, суммы, категории, описания, сумму с символом валюты, UTF-8 BOM, CRLF и escaping кавычек/разделителей. Категория заполняется локализованным отображаемым именем системной или пользовательской категории; дата берётся из `paymentDate`, если она задана, иначе из `createdAt`. Удалённые расходы фильтруются. CSV предназначен для просмотра, не является форматом обратимого backup и не поддерживается импортом.

## Известные расхождения с ожиданиями

- JSON v1 сохраняется для обратной совместимости, но не содержит custom category metadata. Новые экспорты используют v2.
- Импорт CSV не реализован: CSV предназначен для таблиц и просмотра, а не для восстановления данных.

При изменении импорта проверять all-or-nothing (сначала полная валидация, затем write), user-scoped duplicate detection, IndexedDB и синхронизацию; не создавать API calls непосредственно в диалоге.
