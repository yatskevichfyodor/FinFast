# Offline-first и локальное состояние

## Хранилища и разделение

- IndexedDB database `finfast`, текущая версия 7; stores расходов и custom categories. Ключи составные: `[userId, expenseId]` и `[userId, categoryId]`. Upgrade steps вызывают миграции v5 и v7.
- Expense store выполняет read/replace конкретного диапазона user ID. Данные другого профиля остаются отдельными; switching/logout не означает физического удаления IndexedDB.
- Дополнительные user-scoped данные, включая токены/auth markers, скрытые системные категории, category queues и data change timestamps, хранятся в localStorage. Некоторые значения — глобальные/local app settings, сверяться с конкретными storage helpers при изменении.
- `Expense.isSynced`, `isCreatedLocally`, `deletedAt` — внутреннее клиентское состояние синхронизации и tombstone. Не экспортировать/не сериализовать его в публичные DTO без явного требования.

## Offline профили

- **Anonymous:** фиксированный клиентский ID `anonymous`; backend пользователя нет, автоматической синхронизации нет. Расходы остаются локальными.
- **Ранее вошедший аккаунт/offline:** frontend хранит локальные сведения о пользователе и может работать с локальным набором данных. `isOffline` и `isAnonymous` — разные флаги, хотя текущая auth store семантика `isAuthenticated` также считает offline user с ID аутентифицированным для маршрутизации. При изменении guard/interceptor учитывать все эти состояния отдельно.
- Если Auth Service недоступен на экране входа, пользователь может выбрать продолжение без аккаунта. `navigator.onLine` только сообщает о наличии сетевого интерфейса, а не доступность сервиса.

## Сохранение и sync

Расходы сохраняются локально до запроса к backend; успешный API ответ переводит запись в synced. Ошибка/таймаут не должна удалять изменения. Сетевое online событие инициирует попытку Expense Store refresh, а категории используют отдельные pending-operation очереди localStorage и timestamp сравнение. Импорт сохраняется локально и сам по себе не запускает обязательную мгновенную API синхронизацию.

Синхронизация — не универсальный автоматический фоновый механизм для каждого объекта: смотреть конкретные вызовы stores, online listener и UI lifecycle. Детали см. [expense-sync.md](expense-sync.md) и [category-sync.md](category-sync.md).

## Logout и приватность

Logout очищает локальную authenticated identity/tokens и пытается отозвать refresh token на сервере, но не очищает записи IndexedDB и не удаляет pending расходы. UI показывает количество несинхронизированных расходов, которые останутся только на устройстве. Данные не должны отображаться следующему пользователю: store и storage запрашивают записи с текущим user ID. Не заменять это поведение очисткой всей IndexedDB; это уничтожило бы pending user data.

Anonymous transfer требует явного действия UI и сейчас касается только расходов. Не переносить локальные записи автоматически при смене пользователя. Фактическое поведение/флаг переноса описаны в [authentication.md](authentication.md) и [expenses.md](expenses.md).

## Ограничения

- Browser storage не является серверной резервной копией и может быть очищен пользователем/браузером.
- Не полагаться на сетевой статус вместо результата запроса.
- Восстановление IndexedDB версии должно сохранять user scoping и применять новые upgrade migrations; не редактировать уже выпущенные migration steps без необходимости.
- Не хранить пароли; не считать client localStorage доверенной авторизацией backend.
- Logout защищает видимость локальных данных в UI, но данные остаются физически на устройстве для последующего входа в тот же профиль.
